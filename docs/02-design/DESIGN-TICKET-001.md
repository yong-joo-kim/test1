# DESIGN-TICKET-001: 티켓 목록/등록/상세 화면

## 화면 목적
상담원이 AS 티켓을 접수/검색/추적하고, 기사가 배정받은 티켓의 상태를 변경한다.

## 진입 경로
사이드바 "AS 티켓 관리" 메뉴

## 레이아웃 (ASCII 와이어프레임) — 목록 화면
```
+-----------------------------------------------------------------+
| [검색: 고객명/티켓번호] [상태▾] [담당기사▾] [기간▾]   [+ 신규접수] |
+-----------------------------------------------------------------+
| 티켓번호      | 고객명 | 제목        | 우선순위 | 상태     | 담당기사 |
| AS-20260820-1 | 홍길동 | 화면 미출력 | HIGH     | 배정     | 김기사   |
| ...                                                              |
+-----------------------------------------------------------------+
|                         페이지네이션                              |
+-----------------------------------------------------------------+
```

## 구성 요소 및 상태
- 목록 테이블: 로딩(스켈레톤 행 5개) / 빈상태("접수된 티켓이 없습니다" + 신규접수 CTA) / 에러(재시도 버튼) / 정상
- 상태 배지: RECEIVED(회색) / ASSIGNED(파랑) / IN_PROGRESS(주황) / COMPLETED(초록) / CANCELLED(적색 취소선) / HOLD(보라)
  - 색상과 함께 텍스트 라벨 항상 병기 (색맹 접근성)
- 신규접수 모달: 고객 검색(자동완성) → 제품 선택 → 제목/설명/우선순위 입력 → 제출

## 인터랙션 플로우
1. 목록 진입 시 기본 필터: 내가 담당한 것 + 진행중 상태
2. 행 클릭 → 상세 패널(우측 슬라이드오버)에서 상태 변경 버튼 노출 (권한에 따라 활성/비활성)
3. 상태 변경 버튼 클릭 → 사유 입력 필수(HOLD, CANCELLED) → 확인 → 낙관적 업데이트 + 실패 시 롤백

## 디자인 토큰 참조
공용 디자인 시스템(frontend/src/components/ui) 사용, 색상은 상태 배지 팔레트만 신규 정의:
- --status-received: #94A3B8
- --status-assigned: #2563EB
- --status-inprogress: #EA580C
- --status-completed: #16A34A
- --status-cancelled: #DC2626
- --status-hold: #7C3AED

## 접근성
- 상태 변경 버튼은 disabled 시 이유를 title 속성으로 노출 ("다른 기사에게 배정된 티켓입니다")
- 모든 배지는 텍스트 라벨 포함, 키보드로 행 탐색/열기 가능(Tab, Enter)
